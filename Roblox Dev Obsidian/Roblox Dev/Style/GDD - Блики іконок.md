# GDD: Блики іконок

← [[GDD - 2D іконки]]

> [!summary] Один закон
> **Блик — це вершина і два (або три) ребра.** Він завжди сидить там, де сходяться ребра граней, його «руки» лежать **точно на цих ребрах**, на кінцях гострі, а між кінцями контур не дугою, а **прямими лініями йде до точки біля вершини** і повертається — виходить гострий увігнутий кут. Білий, без контуру, без прозорості.

Так зроблено блики в **Free Icon Pack** (див. «Готовий пак» у [[GDD - 2D іконки]]). Коли ми **малюємо чи генеруємо будь-яку іконку в стилі пака** — діаманти, купони, мегафони, значки HUD — блики робимо за цим гайдом, а не «білою смужкою зліва вгорі».

![[glint_anatomy.png]]

## Як будується блик

1. **Знайди вершину V** — точку, де сходяться ребра суміжних граней (кут столика, стик центрального ребра з нижнім, кут верхньої грані коробки). Не середину грані й не випадкове місце.
2. **Вибери 2 ребра** (або 3), що виходять з V. Руки блика йтимуть уздовж них.
3. **Постав кінці рук T1, T2 (T3)** на цих ребрах на відстані від V. Кінець завжди **лежить на самому ребрі**, не поряд.
4. **Внутрішня точка** `I = V + ((T1−V) + (T2−V)) · k`, де **k ≈ 0,15–0,2**. Контур блика: `V → T1 → I → T2 → V`. Усі відрізки **прямі**.
5. **Три ребра** — тризуб: між кожною парою сусідніх кінців своя внутрішня точка, контур `T1 → I12 → T2 → I23 → T3 → I31`.
6. **Заливка** — чистий білий `#fff`, без обводки, без прозорості, без розмиття, без градієнта.
7. **Обріж по силуету** (`clip-path`), щоб блик не вийшов на темний контур. Якщо кінці лежать на ребрах, а ребра всередині силуету, обрізання лише страхує.

## Параметри

| Що | Значення (полотно 256) |
| --- | --- |
| Кількість | великій іконці — 2 (великий і малий); дрібній — 1 |
| Великий блик | на найвиразнішій вершині передньої грані; довжина рук ≈ 35–40 (≈ 15–17% ширини іконки), руки різної довжини |
| Малий блик | на вторинній вершині світлої (верхньо-лівої) сторони; руки ≈ 12–17 (≈ 5–6%), часто 3 ребра |
| Глибина кута | k = 0,15–0,2; у пакових бликів внутрішня точка за 5–7 px від вершини |
| Товщина | не задається окремо: виходить з k і кута між ребрами; біля вершини ≈ 5–7 px, до кінців зводиться в нуль |
| Колір | `#fff` |
| Де | освітлена сторона: зверху й ліворуч; не ставимо блик на найтемнішу грань |
| Контур | `#040435`, блик його не торкається поверх і не виходить за нього |

## Вигнуті форми

Там, де немає ребер (серце, округла бульбашка), роблять **півмісяць**: тонка біла форма вздовж лівого верхнього краю з **загостреними обома кінцями**. Кінці гострі, як у звичайного блика; зовнішня сторона повторює контур, внутрішня — полога дуга. Це **єдиний випадок із кривою**; на гранованих формах криву не використовуємо.

## Типові помилки

| Помилка | Як виглядає | Правильно |
| --- | --- | --- |
| Внутрішня сторона — дуга (`Q`) | «листочок», «ріжок» | прямі відрізки `T1 → I → T2`, гострий кут |
| Заокруглена лінія-смужка | біла «ковбаска» із закругленими кінцями | гострі кінці, форма клина |
| Блик «просто так» на грані | не стикається з ребрами | тільки у вершині стику ребер |
| Руки не збігаються з ребрами | блик «плаває» поруч із гранню | кінці лежать на ребрах, руки повторюють їх напрям |
| Блик виходить на контур | білий на темно-синьому | `clip-path` по силуету |
| Напівпрозорий або із градієнтом | «розмите» світло | `#fff`, суцільний |
| Однакові блики скрізь | штамп | великий + малий, різні довжини рук |

## Рецепт для генерації (для Claude)

Коли генеруємо іконку в стилі пака, **не малюємо блик «на око»**, а робимо так:

1. Побудувати іконку **пласкими гранями** (полігони) — блик не існує без ребер.
2. Записати вершини, де сходяться ребра на освітленій стороні; вибрати одну головну (великий блик) і одну-дві другорядні.
3. Для кожної знайти два (три) ребра, поставити кінці рук на ребра на потрібній відстані, обчислити `I` з k = 0,15–0,2.
4. Нарисувати білий `path`, обрізати по силуету, покласти **останнім шаром** поверх заливки граней.
5. Перевірити за списком нижче й показати у вебі на тлі UI.

Хелпер (`Source/glint_helper.py`, Python, видає SVG `path`):

```python
def lerp(a, b, t): return (a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t)
def dist(a, b):    return ((a[0]-b[0])**2 + (a[1]-b[1])**2) ** .5
def along(V, to, d):            # точка на ребрі V→to на відстані d від V
    return lerp(V, to, min(1.0, d / dist(V, to)))

def glint(V, tips, k=.17, fill="#fff"):
    n = len(tips)
    if n == 2:
        t1, t2 = tips
        I = (V[0] + (t1[0]-V[0] + t2[0]-V[0]) * k, V[1] + (t1[1]-V[1] + t2[1]-V[1]) * k)
        pts = [t1, I, t2, V]
    else:                        # три ребра — тризуб
        pts = []
        for i, t in enumerate(tips):
            nx = tips[(i + 1) % n]
            pts += [t, (V[0] + (t[0]-V[0] + nx[0]-V[0]) * k, V[1] + (t[1]-V[1] + nx[1]-V[1]) * k)]
    d = "M" + " L".join(f"{x:.1f} {y:.1f}" for x, y in pts) + "Z"
    return f'<path d="{d}" fill="{fill}"/>'

# приклад: великий блик діаманта
V = (128, 148)
glint(V, [along(V, (127, 85), 40), along(V, (16, 113), 38)])
```

## Чекліст

- [ ] Кожен блик сидить у вершині, де сходяться ребра граней.
- [ ] Руки лежать на ребрах; кінці гострі.
- [ ] Внутрішня сторона — прямі лінії до точки біля вершини (k 0,15–0,2), не дуга.
- [ ] Білий `#fff`, без обводки, прозорості й градієнта.
- [ ] Обрізано по силуету, не торкається темного контуру.
- [ ] 1–2 блики на іконку, різної довжини, на світлій (верх-ліво) стороні.
- [ ] Круглі форми — півмісяць із гострими кінцями.
- [ ] Порівняно з іконкою пака поруч на екрані.

## Досвід і рішення

| Спроба | Результат |
| --- | --- |
| Блик — біла напівпрозора смужка зліва вгорі | відхилено («блики мають бути як у паку») |
| Заокруглені лінії-відблиски (`stroke-linecap: round`) | відхилено: «це зовсім не те» |
| Клини в кутах граней із дугою всередині (квадратична крива) | краще, але «виходять за контур» і дуга замість гострого кута; клини обрізали по грані |
| Розібрали діамант пака на грані й виміряли блики; блик = вершина + ребра + прямі лінії до внутрішньої точки | **«імба»** — це правило тепер для всіх іконок у стилі пака |
