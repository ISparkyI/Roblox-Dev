# GDD: 2D-іконки та UI

← [[Style]]

> [!summary] Коротко
> Єдиний стиль 2D-графіки інтерфейсу. Шість стандартів:
> 1. **Іконки** — «мультяшний вектор»: товстий темний контур, соковиті градієнти, блиск, іскорки, бейдж дії.
> 2. **Кнопки — стиль A** — усі кнопки UI; білий відблиск, що пробігає, — за замовчуванням.
> 3. **Плитки й чипи — стиль A** — квадратні плитки з іконкою і верхні плашки статусу (візерунок удвічі слабший).
> 4. **Картки й підкладка** — вертикальні картки покращень, широкі плашки, 2D-підкладка зі studs.
> 5. **Загальні правила форми** — без заокруглень, прямокутний блиск, studs.
> 6. **Заголовки й регістр** — заголовки вікон КАПСОМ: Montserrat 900, градієнт, контур, тверда тінь і білий відблиск; де КАПС, де «Кожне Слово», де речення.
>
> Процес завжди один: вектор (SVG) у вебі → показуємо користувачу → після «переносимо» рендеримо PNG і ставимо в гру.

## 1. Іконки

### Стиль

| Елемент | Правило |
| --- | --- |
| Контур | один суцільний темний контур `#14161a` навколо всього силуету; товщина ≈ 4–5% розміру іконки (20–24 у полотні 480). Внутрішні шви — тонші (5–7) і напівпрозорі |
| Заливка | градієнт згори вниз: світлий тон → основний → темний. Бічні грані 3D-предметів темніші за передню, верх — найсвітліший |
| Блиск | світла пляма або смужка (`#fff`, непрозорість 0,35–0,6) у верхній лівій частині форми |
| Іскорки | 1–2 білі чотирипроменеві зірочки біля предмета (одна велика, одна маленька й прозоріша) |
| Значок-бейдж | коло ~25% ширини іконки у правому верхньому чи нижньому куті: темне кільце, градієнтна заливка, білий символ з темним контуром. Символ пояснює дію: «+» — додати, стрілка вгору — більше, блискавка — швидше |
| Перспектива | предмети з об'ємом — в ізометрії (кут 30°), пласкі символи (листок, монета) — прямо |
| Тінь | **без тіні** під предметом (у UI вона виглядала сірою плямою). Об'єм дають контур і градієнти |
| Колір | насичені, без сірого «бруду»; у кожної категорії свій акцент (зелений — удача / ріст, бурштиновий — швидкість / вогонь, бірюзовий — множники, червоний — підставки / ліміти) |
| Фон | прозорий. Іконка має читатися і на світлому, і на темному фоні |
| Розмір | полотно 480 × 480 (viewBox −240…240), PNG 512 × 512. Предмет займає ~80% полотна |

### Побудова

1. **Силует.** Одна проста впізнавана форма, що читається зменшеною до 64 px.
2. **Контур.** Спершу силует темним кольором з товстим обведенням (`stroke-linejoin: round`), потім кольорові частини. Контур рівний по всьому краю, як у наліпки.
3. **Об'єм.** 3D-предмети — три грані (верх світлий, ліва середня, права темна). Пласкі — радіальний градієнт від центру.
4. **Деталі.** 1–3 деталі, що розповідають історію (шви дощок, обмотка ручки, розжарений бік молота).
5. **Бейдж і іскорки** — останніми, поверх усього.
6. **Перевірка** на світлому й темному фоні та в макеті реального UI.

### Процес

1. **Вектор у вебі.** Генератор на Python пише SVG і HTML-сторінку з іконками на різних фонах і макетом екрана. Показуємо й чекаємо рішення.
2. **«Переносимо» → PNG.** SVG рендеримо headless Chromium у PNG 512 px з прозорим фоном (`omitBackground`).
3. **Завантаження** через **Asset Manager → Import** у Studio (не Creator Store). ID — через «Copy ID».
4. **У грі** — `ImageLabel` з `ScaleType = Fit`. ID записуємо в константу скрипта і в нотатку об'єкта.
5. **Збереження** — генератор, SVG і PNG у папці об'єкта (`Source/`, `Preview/`, `Roblox/`).

### Іконки руди — «кристали з каменя»

> [!success] Затверджено («кайф»)
> Руда = **колотий сірий валун, з якого росте кластер кристалів кольору руди**. Кристали **вросли в камінь**: виходять з темного гнізда, їхні основи закривають уламки каменю. Колір руди — лише в кристалах, жилці й крапках; камінь однаковий для всіх руд.

### Іконки кнопок і лічильників — орієнтир

Іконки на кнопках HUD і в лічильниках (магазин — кошик, гроші — пачка купюр, діаманти, квиток, налаштування — шестерня, інвентар — рюкзак тощо) малюємо в нашому стилі, орієнтуючись на ці референси користувача:

- **Що беремо:** один товстий темний контур навколо всього силуету, як у наліпки; соковиті насичені кольори з градієнтом згори вниз; біла пляма чи смужка блиску зліва вгорі; прості впізнавані предмети, що читаються в 48–64 px; маленькі бейджі-знаки («+», «!», «x2») у куті.
- **Чого не беремо:** пласкі емодзі без контуру (як у четвертому референсі), тіні під предметом, дрібні деталі й написи, що губляться в малому розмірі.
- **Як ставимо (HUD головного екрана, оновлено 25.10.2026):** кнопки — **іконка на плитці стилю A свого кольору** (плитка ≈0,92 кнопки, іконка ≈0,78 плитки, без відблиску); великі кнопки-покупки й таймери (множник грошей, бос) можуть лишатися без плитки. Раніше (до 25.10.2026) було **без підкладок і плиток** — лише іконка і під нею великий підпис (Montserrat 900, білий, темний контур ≈ 0,22 від розміру шрифту `#14161a`), що **залазить на низ іконки приблизно на 85% висоти шрифту**. Маленькі кнопки верхнього ряду — **без підпису**, висотою як кругла кнопка чату Roblox (≈ 40 у розмірах макета). У лічильнику — іконка зліва від числа на темній напівпрозорій плашці, що зникає праворуч. Квадратні кнопки стилю A з написом (розділ 2) лишаємо для вікон і діалогів.

Контур у паку — дуже темний синій `#040435`, наш у векторних іконках — `#14161a`. Різниця мала, але перед тим як ставити іконки пака поруч з намальованими нами, перевіряємо їх разом на екрані.

**Як використовуємо.**

1. Шукаємо значок у каталозі: для кнопок і лічильників — `1st Outline`, 256 px (іконки в грі зазвичай ≤ 128 px, 256 дає запас під масштаб); для дрібних лічильників — `64px`.
2. Потрібні PNG користувач завантажує через **Asset Manager → Import** (не Creator Store), ID записуємо в константу скрипта й нотатку об'єкта (як для решти іконок).
3. У грі — `ImageLabel`, `ScaleType = Fit`; іконка стоїть на кнопці або плитці стилю A (розділи 2–3). Усі іконки одного ряду беремо з однаковим стилем (усі `1st` або усі `2nd`).
4. Оригінали не змінюємо. Якщо треба інший колір чи додатковий елемент — робимо копію поруч, не чіпаючи файл у паку.

| Блики | **гострі білі «зубці» в кутах граней**: білий клин, що лягає вздовж двох ребер, що сходяться, і звужується до точки на кінцях (увігнута третя сторона). На круглих формах (серце) — білий **півмісяць** із загостреними кінцями вздовж краю. Ніяких заокруглених ліній-відблисків |
| Обрізання бліків | кожен блик **обрізається по формі своєї грані** (`clip-path`), щоб не виходив на темний контур |
| Колір за змістом | допоміжні іконки — **переважно білі/світло-блакитні** (не яскраві), один-два кольорові акценти (серце, зірка, смужка); золоті — лише «цінні» (тікет) |
| Поза | предмет під кутом (купон −24°, мегафон −16°, тікет +14°), щоб з'явилась висота; кути вписуємо так, щоб габарит по висоті збігався з сусідніми іконками |

**Рядок іконок однакової висоти.** Усі іконки одного ряду обрізаємо по видимому габариту (прозорі поля зрізаємо) і масштабуємо до **однакової висоти**; ширина може відрізнятися (купон ширший за мегафон). Проміжок між іконками ряду однаковий (≈ 18 у макеті, ≈ 45% висоти).

**Стовпчик іконок у списку** (наприклад, плашка множників): усі іконки вписуються в **однакову рамку** (та сама ширина й висота, `ScaleType = Fit`), а не кожна за своїми пропорціями — інакше ширша іконка вилазить лівіше / ширше за сусідні й стовпчик виглядає кривим.

**Як робимо (генератор):** SVG на Python — функції `ext` (видавлювання), `wedge` (клин-блик), `clipPath` для обрізання, `poly` (пласка грань); рендер у PNG 256 з прозорим фоном (headless Chromium, `omitBackground`). Приклад генератора й готові SVG/PNG — у папці відповідного об'єкта (`Source/`, `Roblox/`).

Генератор — `Source/gen_buttons.py` (`button(style='A', …)`, `pattern_a`, палітра `PAL`).

### Анатомія

`h` — висота кнопки, `w` — ширина. Усі шари — прямокутники **без заокруглень**.

| # | Шар | Правило |
| --- | --- | --- |
| 1 | Контур | уся кнопка кольором `outline` (дуже темний тон кольору кнопки, **не** `#14161a`). `O = max(3, round(0,04·h))` |
| 2 | Світла рамка | усередині контуру, колір `border`. `B = max(2, round(0,028·h))`; видно зверху і з боків |
| 3 | Грань | площа над губою: x = y = `O + B`, ширина `w − 2(O + B)`. Вертикальний градієнт `top` (0) → `mix(top, bottom, 0,62)` (0,55) → `bottom` (1) |
| 4 | Візерунок | «квадратик + L», лише на грані (див. нижче) |
| 5 | М'яке світло | радіальний градієнт на всю грань: центр (50%, 18%), радіус 0,7, білий 28% → 0 |
| 6 | Світла лінія | під гранню, висота `max(2, round(0,035·h))`, колір `line`, **непрозорість 0,75** |
| 7 | Губа | темніша смуга по низу всередині контуру, висота `max(6, round(0,12·h))`, колір `lip` |
| 8 | Напис / іконка | по центру **грані** (не губи) |

`mix(a, b, t)` — змішування RGB; `dark(c, k) = mix(c, #000, k)`, `light(c, k) = mix(c, #fff, k)`.

Приклад 400 × 100: контур 4, рамка 3, губа 12, лінія 4, грань 386 × 73, клітинка 18,25, шрифт 38.

### Візерунок «квадратик + L»

- **Сітка** квадратна: клітинка = висота грані / 4 (`h ≥ 70`) або / 3 (малі кнопки й чипи). Починається з верху грані, по горизонталі центрована.
- **Шахівниця** з двох мотивів: у ряду чергуються, наступний ряд зсунутий на клітинку (тайл 2 × 2).
- **Мотив** — квадрат 0,48 клітинки по центру клітинки. Тон від `mid = mix(top, bottom, 0,5)`.

| Частина | Колір | Непрозорість (кнопки) | Плитки й чипи (× 0,5) | Лінія |
| --- | --- | --- | --- | --- |
| «Квадратик» — заливка | `dark(mid, 0,32)` | 0,22 | 0,11 | — |
| «Квадратик» — світлий край (верх-ліво) | білий | 0,35 | 0,175 | 0,07 клітинки |
| «Квадратик» — темний край (низ-право) | `dark(mid, 0,45)` | 0,45 | 0,225 | 0,07 клітинки |
| «L» (ліва сторона + низ) | `dark(mid, 0,45)` | 0,42 | 0,21 | 0,085 клітинки |

### Відблиск

Обов'язковий для клікабельних кнопок (на прохання користувача — сильніший, ширший і повільніший, ніж перша версія).

| Параметр | Значення |
| --- | --- |
| Форма | дві скошені білі лінії — широка й тонка — на всю кнопку, обрізані по її краю |
| Ключі прозорості (позиція → прозорість) | `0→1`, `0,32→1`, `0,40→0,15`, `0,48→1`, `0,51→1`, `0,55→0,35`, `0,59→1`, `1→1` |
| Кут | `Rotation 25` |
| Прохід | `Offset` від −1,3 до 1,3 за **1,8 с** (Sine InOut), зліва направо |
| Ритм | перший — через випадкові 1–4 с, далі кожні 4–8 с (випадково, у кожної кнопки свій таймер) |
| Де | усі клікабельні кнопки; **не** на сірих (недоступно / `MAX`); лише коли кнопка на екрані |

**Roblox:** білий `Frame` на всю кнопку (без `UICorner`, `Active = false`) у кнопці з `ClipsDescendants = true` + `UIGradient` (`Transparency` — ключі вище, `Rotation 25`); `TweenService` тягне `Offset.X` −1,3 → 1,3.

### Як будувати

- **Веб:** SVG — прямокутники без `rx`, `linearGradient` (грань), `radialGradient` (світло), `pattern` з `patternUnits="userSpaceOnUse"` (тайл 2 × 2, x/y = початок сітки), `clipPath` по грані; Montserrat 900 вбудований. PNG — headless Chromium.
- **Roblox:**
  - **Основа** (контур, рамка, грань, світло, лінія, губа) — PNG як `ImageButton` / `ImageLabel` з `ScaleType = Slice`; `SliceCenter = Rect(O + B, O + B, w − O − B, h − O − губа − лінія)`.
  - **Візерунок** — безшовний PNG-тайл 2 × 2 клітинки, `ScaleType = Tile`, `TileSize = 2·клітинка`, у `Frame` розміром з грань з `ClipsDescendants = true`. Тайл свій для кожного кольору.
  - **Напис** — `TextLabel` (Montserrat Heavy, білий, `UIStroke` `#14161a`, `Contextual`, ≈ 0,08 розміру шрифту).
  - **Зміна стану** = заміна картинки основи й тайла.
  - Альтернатива: окремий PNG під кожен розмір кнопки.

### Наведення на картку

Картки покращень реагують на мишку — це правило для всіх екранів покращень у цьому стилі (і для нових теж).

| Що | Правило |
| --- | --- |
| Розмір | картка з тінню разом збільшується **×1,05** від свого розміру в спокої |
| Нахил | до **3°** у бік мишки: мишка біля правого краю — картка нахиляється праворуч, біля лівого — ліворуч, по центру — рівно |
| Плавність | згладжування ~0,12 с (експонента), без пружини; після відведення мишки — плавно назад |
| Коли не реагує | картки під затемненням «недоступно» |
| Кнопка на картці | має своє наведення (1,04), разом з карткою |

У Roblox: картка й тінь лежать у тримачі `CanvasGroup` (центр — у центрі картки, запас 16 px з усіх боків, щоб обводка й тінь не обрізались), масштаб — `UIScale`, нахил — `Rotation`. `CanvasGroup` потрібен, бо у повернутих елементах `ClipsDescendants` не працює, а візерунок кнопок стилю A обрізається гранню. У `SurfaceGui` положення мишки на полотні рахуємо променем з камери на грань деталі.

## 5. Загальні правила форми

| Правило | Як |
| --- | --- |
| Без заокруглень | усі UI-елементи квадратні (кут **0**): вікна, панелі, картки й тіні, кнопки, чипи, бари й заливки, плитки, затемнення. Контури з гострими кутами (`stroke-linejoin: miter` / `UIStroke.LineJoinMode = Miter`). Круглими лишаються тільки бейдж, галочка і самі studs |
| Блиск | ніколи не окремий овал чи «пігулка» — прямокутна смужка зверху на всю внутрішню ширину (~35–40% висоти, білий 25–35%); на великих картках — білий вертикальний градієнт; на кнопках стилю A — радіальне світло |
| Studs на табличках | легка сітка (білий stud + чорна «L»-тінь), шар видно на ~14%, згасає догори (видно повністю внизу, 0 угорі). У кнопок, плиток і чипів studs немає — у них візерунок стилю A |

### Відблиск, що пробігає

Більше **не додатковий**: увімкнений за замовчуванням на клікабельних кнопках — параметри в розділі 2 («Відблиск»); на заголовках — у розділі 6. Стара версія (0,65 с, Quad InOut, кожні 3,5–6 с, лише зелені кнопки й закриття) — замінена.

## 7. Модальні вікна: розмір, місце, гортання

- **Один розмір для всіх модальних вікон гри.** Рамки вікон мають однакові пропорції (≈ 1,856 : 1), заголовок і хрестик — у тих самих пропорціях до рамки. На екрані рамка займає ≈68 % ширини, а блок «заголовок + рамка» — ≈72 % висоти. Вікна масштабуються під екран і на великих моніторах теж (не обмежувати масштаб одиницею).
- **Місце:** рамка по центру по горизонталі; по вертикалі блок «заголовок + рамка» стоїть по центру вільної зони між верхньою смугою Roblox (`GuiService.TopbarInset`) і хотбаром. На телефоні — максимум, що влазить, з невеликими полями.
- **Якщо вміст не влазить — не збільшувати вікно, а гортати.** Список стоїть у вікні перегляду (`ClipsDescendants`) з лаймовим повзунком (вертикальним справа або горизонтальним знизу) і гортається коліщатком, повзунком, кліком по доріжці і **затиском мишки / пальця** на самому списку.
- **Закриття:** X, Esc або клік **поза** рамкою. Клік по порожньому місцю всередині вікна (панель зі studs, проміжки між слотами) вікно не закриває; клік, яким закрили підтвердження всередині вікна, теж не має «провалюватися» в тло.
- **Швидкі дії з вибраним предметом:** якщо предмет вибраний, кнопки-інструменти (замок, кошик) діють одразу на нього (кошик — через підтвердження); якщо нічого не вибрано — вмикають режим вибору кількох. Повторний клік по вибраному слоту знімає вибір.

## 8. 3D-іконки предметів у слотах

Для предметів, у яких є 3D-модель у грі (руда, злитки), слот показує саму модель у `ViewportFrame` замість PNG, щоб іконка й предмет у світі були однакові.
- **Контур:** 8 темних силуетів моделі (та сама модель, чорна без світла, тонована `#14161a`), зсунутих на 2 px у 8 напрямках, під кольоровою моделлю — читається на будь-якому фоні.
- **Кут, масштаб і зсув** задаються для кожної моделі окремо (ракурс ≈30° по горизонталі й вертикалі); модель має стояти в **своєму квадраті** слота: не налазити на назву, кількість і кнопки, не виходити за межі.
- Порожній або заблокований слот: та сама модель напівпрозора й сіра (повторює `ImageTransparency` / `ImageColor3` мітки).
- Предмети без моделі (зілля, голови големів) — як і раніше, PNG.
