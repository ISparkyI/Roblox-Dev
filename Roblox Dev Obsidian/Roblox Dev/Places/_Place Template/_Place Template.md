# _Place Template

← [[Places]]

Шаблон плейсу і **керівництво, як створити новий плейс**. Папка нового плейсу копіює цю структуру; у назвах нотаток `_Place Template` замінюється назвою плейсу.

- [[_Place Template - GDD|GDD]] — дизайн гри (заготовка)
- [[_Place Template - 3D Models|3D Models]] — класи моделей і моделі
- [[_Place Template - Scripts|Scripts]] — Server, Client, Modules
- [[_Place Template - 2D|2D]] — інтерфейс, іконки, декалі, текстури

## Структура папки
```
Places/<Place>/
  <Place>.md                         ← тільки посилання: вгору на Places, вниз на розділи
  GDD/<Place> - GDD.md               ← загальний дизайн гри + таблиця систем
  GDD/GDD - <System>.md              ← дизайн однієї системи (дочірня GDD)
  3D Models/<Place> - 3D Models.md   ← список класів
    <Class>/<Class>.md               ← список моделей класу
      <Model>/<Model>.md             ← опис однієї моделі
      <Model>/Roblox/                ← GLB для Studio
      <Model>/Source/                ← генератори (Python)
      <Model>/Preview/               ← прев'ю, знімки
  Scripts/<Place> - Scripts.md
    Server/<Place> - Server.md (+ .lua)
    Client/<Place> - Client.md (+ .lua)
    Modules/<Place> - Modules.md (+ .lua)
  2D/<Place> - 2D.md
```

## Як створити новий плейс
1. **Папка й назви.** Створи `Places/<Place>/` і всі нотатки з дерева вище. Назви нотаток і папок — англійською.
2. **Головна нотатка.** `<Place>.md` містить **тільки посилання**: `← [[Places]]` і діти (GDD, 3D Models, Scripts, 2D). На глобальні нотатки (стилі, ефекти, плагіни) плейс **не посилається**.
   - Глобальне плейс отримує через **Roblox**: у нотатці Roblox є таблиця «Що Roblox передає плейсам». Додай туди рядки для ресурсів, які використовує новий плейс.
   - Як саме плейс використовує ці ресурси, описується в його GDD звичайним текстом.
3. **GDD плейсу.** Скопіюй [[_Place Template - GDD|заготовку GDD]] і заповни. Тут описується гра загалом, взаємодія моделей і сцена в Roblox Studio. Коли система виростає (рол, економіка, інтерфейс…), винось її в окрему нотатку `GDD - <Система>` у папці GDD, а в GDD лишай короткий опис і рядок у таблиці «Системи». Кожна модель, об'єкт, вікно й локація — у своїй нотатці; GDD посилається на них obsidian-посиланнями.
4. **Класи моделей.** Кожен клас (Golems, Ores, Instruments…) — окрема папка з хабом `<Class>.md`, який посилається тільки вгору (`← [[<Place> - 3D Models|3D Models]]`) і на свої моделі.
5. **Моделі.** Нотатка моделі посилається тільки на свій клас (`← [[<Class>]]`) і вбудовує свої картинки (`![[preview.png]]`). Вона описує лише саму модель: форму, палітру, файли, анімації. Інші класи, скрипти й глобальні нотатки в ній не згадуються посиланнями.
6. **Скрипти.** Код, що працює в Roblox, лежить у `Scripts/Client|Server|Modules` з рядком у таблиці відповідної нотатки. Опис звичайним текстом, без посилань на моделі.
7. **Глобальне не чіпаємо.** У нотатки `Style`, `Effects`, `Plugins`, `Scripts` (глобальні) нічого про цей плейс не дописуємо. Якщо створено новий спільний ефект чи стиль, він описується загально, без згадки плейсу.

## Правила зв'язків (коротко)
| Хто | Може посилатися на |
| --- | --- |
| `<Place>.md` | Places (вгору), свої розділи (вниз) |
| Розділ плейсу (GDD, 3D Models, Scripts, 2D) | плейс (вгору), свої підрозділи (вниз); GDD → свої `GDD - <Система>` |
| `GDD - <Система>` | GDD (вгору); на моделі й об'єкти — тільки obsidian-посиланнями |
| Клас (`Golems`, `Ores`…) | 3D Models (вгору), свої моделі (вниз) |
| Модель | свій клас (вгору), власні картинки |
| Глобальні нотатки | тільки своя гілка: Roblox → розділ → нотатка |
| Roblox | усі розділи; зв'язок «глобальне → плейс» тільки текстом у таблиці «Що Roblox передає плейсам» |
